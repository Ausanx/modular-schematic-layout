# 两项电子设计 Skill 的仓库设计

**状态：** 待用户审阅  
**日期：** 2026-10-21

## 目标

在现有 GitHub 仓库 `Ausanx/modular-schematic-layout` 中维护两项相邻但职责清楚的 Codex skill：一项指导原理图的可读性与视觉组织，另一项指导 PCB 的板级设计与审查。保留现有原理图 skill 的通用设计哲学和已建立的评测，同时让新的 PCB skill 能基于适用标准、器件资料、项目约束和板厂能力给出可执行建议。

最终由一个根级中英文 README 说明两者的适用场景、边界、独立安装方式和验证局限。两个 skill 可以单独使用；完整硬件工作流可以先整理原理图/连接基线，再进入 PCB 阶段。

## 已确认的设计决定

- 保留现有 GitHub 仓库及远端名称，不拆成两个仓库。
- 将原理图 skill 迁入独立目录；新建并列的 PCB skill 目录。
- 原理图 skill 是通用的可读性、拓扑表达和视觉一致性规范，不限定特定电路、芯片或器件阵列。
- PCB skill 是通用的板级设计与审查规范，覆盖电气和物理实现、制造与装配约束；不限定某个项目板型。
- 两个 skill 独立触发和安装，不增加路由 skill。仓库 README 解释职责分工及需要两者时的衔接顺序。
- 以适用标准和厂商资料作为可追溯依据，不声称仅靠 skill 即符合标准或获得认证。
- 原理图保留现有 8 项合成 evals。PCB 新增少量与具体用户项目无关的合成任务。
- 用户已要求将两个 skill 发布到 GitHub 同一仓库；完成后应更新 `main` 并提供同一仓库中的安装与发布入口。

## 职责边界

### `modular-schematic-layout`

面向原理图生成、重排和审查，重点是读者能否找到功能、追踪局部拓扑、区分总览/实现/接口页，并看清统一的文字、符号和页面结构。保留目前已有原则：按功能和真实关系组织，不按器件种类停车；依电路实际拓扑选择方向，不将所有结构压成单向链；跨页或共享信号可用适当接口；位号、数值等字段紧贴所属器件；最终图面不得存在未解决的文字、符号、导线遮挡或页面裁切。

处理现有设计时，以用户提供的器件身份、属性、引脚到网络关系为电气基线。skill 的职责是表达和版面优化，不因视觉对齐而更改连接、器件值、极性、隔离关系或地网；缺少原生文件或可读连接信息时，只对能够观察的范围作结论。保留现有 8 项评测及合成图像，迁移时更新相对路径，不将这些有限样例描述为完整 EDA 验证。

### `pcb-design-guidelines`

面向 PCB 规划、布局、布线指导与板图审查。开始建议前整理可用的约束：板框/层数/叠层、器件封装和机械边界、关键网络/接口、阻抗要求、工作电流与热环境、隔离和适用安全要求、组装/测试需要、目标板厂能力及所用 CAD。信息缺失时区分已知约束与假设，针对高影响缺项提出需要确认的事项。

设计顺序以可追踪的物理关系为主：先分区和安排连接器、固定器件及关键功能单元；围绕电源开关回路、去耦回路、敏感输入、时钟/高速接口及其真实回流路径安排优先级；再规划层叠、参考平面、阻抗、布线、热扩散、隔离、测试和装配检查。避免把某个拓扑的局部经验写成所有 PCB 的固定几何规则。电流线宽、阻抗、热升、间距与爬电距离等数值必须依据适用标准/计算方法、真实材料与层叠、器件资料、产品要求和板厂能力确定。

实际布局/布线审查应基于可读取的 CAD 数据、渲染图或明确的约束资料；只有截图时限定结论范围。DRC、阻抗场求解、热/载流计算、Gerber 检查和板厂规则检查只有在实际执行并检查结果后才能报告通过。不得把整洁外观或 schematic 端的可读性当作物理实现验证。

## 规范来源与使用限制

原理图 skill 的来源索引应包含适用范围说明：

- [IEC 61082-1:2014](https://webstore.iec.ch/en/publication/4469)：电工技术文件的编制规则，作为文档组织和表达背景。
- [IEC 60617](https://webstore.iec.ch/en/publication/2723)：图形符号数据库，作为符号语义依据。
- [IEC 61175-1:2015](https://webstore.iec.ch/en/publication/22490)：电工系统中信号的指定，作为信号标识参考。
- [IPC-2612:2010](https://www.ipc.org/TOC/IPC-2612.pdf)：电子产品制造文档要求，作为电子设计文件表达参考。

PCB skill 的来源索引应区分标准与实用应用资料：

- [IPC-2221C:2023](https://www.electronics.org/TOC/IPC-2221C-TOC.pdf)：通用 PCB 设计要求背景，不取代具体产品规范。
- [IPC-2152](https://www.ipc.org/TOC/IPC-2152.pdf)：导体载流能力与温升设计参考；不能脱离导体结构和热条件简化成单一通用线宽。
- [IPC-7351B](https://www.electronics.org/TOC/IPC-7351B.pdf)：表面贴装元件 land pattern 设计参考；具体封装以器件封装图和库验证为准。
- [IPC-6012E](https://www.electronics.org/TOC/IPC-6012E-toc.pdf)：刚性印制板资格与性能要求背景；实际验收按采购等级/合同和板厂能力确定。
- 厂商应用资料示例：[TI AN-1149](https://www.ti.com/lit/an/snva021b/snva021b.pdf)、[Analog Devices AN-1119](https://www.analog.com/en/resources/app-notes/an-1119.html)、[Infineon AP2402635](https://www.infineon.com/assets/row/public/documents/30/42/infineon-ap2402635-general-pcb-applicationnotes-en.pdf)。应用资料只对其讨论的器件/拓扑提供实践参考，不当作普遍标准。

实施时再次核实版本与发布状态。免费目录页、标准目录或受版权保护的正文不可混为一谈；仓库保留链接和简短的适用范围说明，不复制标准正文。设计指南不能替代适用法规、产品认证、当前标准全文、器件数据手册、合同或板厂 DFM 检查。

## 工作流与评测

两项 skill 都保留各自的输入边界和交付说明。原理图输出的连接基线和物理/功能约束可交给 PCB 阶段；PCB 阶段不会将原理图图面检查视作 PCB 规则通过。单项任务无需载入另一 skill 的规则。

现有 8 个 schematic evals 及 fixtures 整体迁移，修正仓库相对路径后继续使用。新建 PCB 合成 evals，至少覆盖：

1. 有输入/开关/储能/整流/输出回路的功率级，评价关键回路、去耦和回流路径是否根据真实连接组织。
2. 含敏感模拟信号与时钟/高速接口的混合信号板，评价分区、参考平面连续性、约束驱动的层叠/阻抗与返回路径处理。
3. 有板框、连接器、机械/装配要求和板厂限制的布局审查，评价固定约束、可制造性、测试可达性及未知项处理。

以上为覆盖面，不代表三个任务足以验证所有板型或 CAD 工作流。每项评测按具体证据检查：保留输入连接/封装/机械约束；优先级有依据；计算或规则检查来源明确；不补造数据；区分实际执行与建议执行的检查。确实需要视觉质量判断时使用可查看的合成图，并实际打开图像，而不是靠文字关键词判分。只有输出建议的 evals 不声称已完成原生 CAD 修改或 DRC。

## 安装与发布

保持仓库名和 GitHub remote 不变。根级 README 中英版本均列出两个 skill 的用途和独立安装命令，例如通过 Skills CLI 分别指定 `modular-schematic-layout` 与 `pcb-design-guidelines`。支持 `.skill` 格式的客户端可从同一个 GitHub Release 获取各自的 skill 包；每个包只含对应 skill 的 `SKILL.md` 与实际引用的资源，不混入评测夹具或另一个 skill。

仓库采用一个共同的 GitHub 发布版本，单次版本发布可以同时包含两项技能，但每个包单独构建和验证。由于目录结构从单 skill 根目录调整为双 skill 仓库，实施计划提出以 `v0.5.0` 作为此次仓库发布版本；当前用户可见的 README 更新记录为 v0.4.1，而 Git tag 最新为 v0.4.0，实施时先核实远端 tag/release 状态再创建版本，不覆盖现有 tag。发布动作包括验证、提交、推送 `main`、创建新 tag/Release 并附上两个包；仓库是 canonical source。

## 成功标准

- 根目录有简洁的中英文仓库 README，准确说明两个 skill 的区别、范围、独立安装和协同方式。
- 原理图 skill 迁移后仍保留用户此前确认的通用设计哲学、统一风格、拓扑表达、标注归属和零遮挡要求；现有评测及图片链接均有效。
- PCB skill 可独立触发，针对输入约束给出板级布局/布线设计建议或审查；来源、假设、适用限制和实际验证情况明确。
- PCB 内容不把某个器件、项目、单一板型、固定线宽或统一留白阈值推广成通用规则。
- 两项 skill 的 frontmatter、名称、相对引用与 package 通过技能验证器；README 安装命令和两个 `.skill` 包均经过实际验证。
- evals 可解析，PCB 场景能分别检查电源/回流、混合信号/高速、可制造性；文档不宣称未运行的 DRC、ERC 或认证已通过。
- 仅公开当前仓库已有公开截图和新的独立合成数据；用户项目文件和私人审查内容不进入仓库。
- 所有验证通过后，将同一仓库更新至 GitHub，并在 Release 中提供两个独立技能包。

## 非目标

- 不对用户当前硬件项目重新选型、计算或改写已确认的逻辑/网表。
- 不复制标准全文，不宣称这两个 skill 可取代合规工程师、产品法规、完整 CAD 检查或认证流程。
- 不为单一芯片、指定板型、某种 EDA 或固定器件排列建立专属模板。
- 不建立新的路由 skill、独立仓库、生成服务或测试框架。
