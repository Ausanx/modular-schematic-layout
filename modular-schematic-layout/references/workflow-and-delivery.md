# 原理图工作流与交付证据

本参考文件把复杂 PCB 项目技能中的通用执行纪律迁移到原理图任务。它不规定某个 EDA、芯片、页数或字体尺寸；具体工具规则仍以目标工程和对应版本的官方资料为准。

## 任务模式

开始前先从用户范围中选择一种模式，并在输出中写明边界：

- **新建/生成**：根据已确认的需求、连接表或网表创建可编辑原理图。
- **重排/优化**：保留器件、值、引脚映射、极性和连接基线，只改善拓扑表达、分页和图面。
- **改版**：从有效原生工程和变更范围开始；保留旧版基线，检查受影响页和跨页映射。
- **审查**：只报告可见证据、风险和建议，除非用户授权修复，否则不改源文件。
- **只更新 skill**：只修改规则文件，不启动 EDA、不安装软件、不修改项目工程。

任务模式不能由文件名推断。用户要求的输出格式、是否允许修改、是否需要原生工程和是否需要 ERC/网表证据都要单独记录。

## 输入基线与状态分类

先建立最小项目记录，至少包含：

| 项目 | 记录内容 |
| --- | --- |
| 文件身份 | 原生工程/网表/PDF/截图的路径、版本、来源和读取状态 |
| 电气基线 | `位号 + 真实引脚号 → 网络`、器件值/型号、极性、多单元归属、地/电源域 |
| 图面基线 | 页名、层级、图幅、坐标单位、网格、符号库和已确认样式 |
| 机械/接口基线 | 连接器针号、配接方向、测试点和已有跨页映射 |
| 约束状态 | **已确认**、**计算初估**、**建议起点**、**待确认** |

图片或 PDF 只能证明可见图面关系；无法读取原生对象时，不能把目视连线、同名文字或图形接触写成网表事实。缺少输入时只阻塞依赖它的结论，继续完成不依赖它的排版和问题定位。

## 工具能力与执行边界

- 只有在实际生成或修改工程时才检测 EDA 版本、文件格式、读写、保存重开、渲染和 ERC/网表比较能力；只审查或只更新 skill 不启动安装流程。
- 工具握手、脚本无报错、文件存在、保存成功、重开对象一致、渲染可读和 ERC/网表实际通过是不同状态，分别记录证据。
- 对陌生格式先在副本中做一个小对象的写入—保存—独立重开—回读试验，再批量修改。超时或断线后先检查已生成的文件和当前会话，避免重复创建或覆盖。
- 不臆造 API、菜单、库标识或私有路径；优先复用目标版本的原生接口和官方文档。没有执行器时交付可审阅的方案和待执行清单，不声称已生成原生工程。

## 阶段记录与退出判据

对实际执行的阶段写出“输入基线—退出判据—实际证据—未闭合项及影响”：

1. **结构**：功能区、主路径、支路、反馈、耦合和跨页边界已识别。
2. **表达**：拓扑、模块边界、标签范围、分页和项目样式已落实。
3. **标注**：位号、数值、针号、网络名和备注的归属可读，没有遮挡、漂移或裁切。
4. **电气保真**：原生对象、引脚到网络成员关系和多页映射与基线一致；实际运行的 ERC/网表检查另列范围和结果。
5. **交付**：源文件、依赖、渲染预览、检查记录和恢复入口齐全，另一位工程师可以打开和继续维护。

视觉检查与电气检查必须分开报告。图面干净不等于 ERC 通过；ERC 通过也不等于标注归属和分页可读。

## 可恢复交付

长任务每次保存后记录当前源版本、已完成页/模块、待处理对象、输出路径和检查范围。源、项目库、脚本和渲染结果尽量使用相对可交付路径；许可不能分发的库要注明准确获取方式。冻结后再改符号、字段、页序或工程设置，先把受影响的结论标为待复核并运行针对性回归。

## 交付清单

- 绘制/优化：可编辑原生源（或明确的 SVG/Canvas/SKiDl 源）、所需依赖、整页及关键局部渲染、连接基线摘要、实际执行的 ERC/网表/渲染检查和未闭合项。
- 审查：页/模块/位号定位、可见证据、影响、最小修复步骤、检查范围和无法确认的事实；不把建议写成已修改。
- 任何模式：标明哪些是视觉证据、哪些是电气证据、哪些仍需目标 EDA、器件资料或人工确认。不要用“最终版”文件名代替验证。
